- #64: T141, `go run ./tools/ci setup` installs the pinned mise.
  - The copy lives in the user cache directory by the XDG Base
    Directory rule on Linux and macOS alike: an absolute
    `$XDG_CACHE_HOME`, otherwise `$HOME/.cache`. `os.UserCacheDir` was
    dropped: on macOS it names `~/Library/Caches`, which the first CI run
    found. REQ-1236, the T141 task and the mise bootstrap decision say so.
  - Gate: code-reviewer and security-auditor. Fixed: a download an
    interrupted setup left behind is removed; no transparent
    decompression; the file is made executable through its descriptor;
    a cached copy its owner cannot run, or others can write, is not used.
  - The shim fact in the T141 task was corrected by measurement: mise
    2026.10.3 links each shim to the first `mise` on the search path.
  - TestReqsReads held `reqMarks` to five seconds and failed on
    macos-26-intel at 7.7 s. It now counts the bytes read, at most two
    lengths of the line; a mutation that counts from the line's start
    fails it.
  - This closes "t141-setup-installs-the-pinned-mise".

Lessons for the process:

- A test bound by wall-clock time fails on a slow runner, not on a bug.
  Bound the work done (bytes read, calls made), not the seconds spent.
- `os.UserCacheDir` is not the XDG rule on macOS. Name the rule and
  implement it.
- Done is CI green on every runner, not a pull request opened or a
  first runner passed.
