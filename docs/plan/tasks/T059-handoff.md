# T059 - `handoff`

Goal: `handoff write|show|list`, the reader, the SessionStart print and
its bound, the three gap-line goldens, SessionEnd and SessionStart in
both orders.

Re-plan (2026-10-12): Kept. The J5 scenario function moves to T075 with
the other remaining scenario functions; the container e2e asserts both
hook orders here, as the row says. The manifest type comes from T135,
and the schema is generated by `tools/schemagen` (T125).
`internal/handoff` holds the types, the reader and the SessionStart
print and imports `memstore` and never `memstore/write`; the write path
of `handoff write`, with the store lock, lives in
`internal/cmd/julieta/handoff`.

- Acceptance:
  - `write` refuses a narrative without its headings (six for `final`)
    and stamps the front matter; `--facts` has no body;
    `schemas/handoff.v1.json` is generated.
  - `handoff write` takes the store lock of its target dir before its
    first git read and releases it at exit; with the lock held by
    another process, `handoff write --facts` waits until it is released
    (a test seam, no sleep).
  - After each facts write, `handoff write --facts` keeps the newest 50
    facts files and every narrative in `handoff/`; the newest facts file
    is never removed (08 8.1, 8.6).
  - The handoff reader returns the greatest ULID among `clear` and
    `final` as the narrative; a later `facts` file does not hide it. The
    decoder is `go.yaml.in/yaml/v3` with `KnownFields(true)`: a front
    matter with an anchor, alias, merge key or include, a duplicate key,
    an unknown key, or over the file cap, is refused, one fixture each;
    the reader refuses a newer version with `RJ-311`; a fuzz target over
    the handoff file decoder has its seeds committed (10 10.1, Fuzz).
  - The container e2e runs SessionEnd and SessionStart in both orders
    (Q22). julieta records in its state the time of the last
    SessionStart and SessionEnd hook runs (08 8.2).
  - `show --hook` prints, in this order, julieta's warnings (one line
    each, the kinds of 08 8.2 item 1), the fixed line `built-in memory
    is disabled, use julieta memory add`, the latest narrative or the
    gap line of 08 8.3, the facts that changed since it, open entries
    not tagged `lesson` newest first, and open `lesson` entries newest
    first; each item carries its repo label, and agent-written text sits
    under the line that says so. Goldens (10 10.1): the print whole, and

    julieta memory list` and whose warnings are all present.

  - The first `show --hook` after a default-branch move prints
    `default-branch-moved` and clears it; the second does not print it.
  - A forced failure in `handoff show --hook` and in `handoff write
    --facts` exits 0, prints one stdout line naming the failure and
    `julieta status`, and records a hook failure; `julieta status` lists
    it and the next SessionStart prints it until the hook next succeeds

Decisions taken while building (2026-10-20), each with what reopens it:

- `internal/memstore/write` exports `Lock(path, onWait)` and
  `AtomicWrite(root, p, data, now, ulids, create)`, which `Store` uses
  unchanged in behavior and `handoff write` calls, so the lock and the
  atomic write exist once. The file is added to `owns` above. Reopened
  by a third writer that needs another option.
- `dirty` in the handoff front matter is the number of kinds of change
  the working tree holds (staged, unstaged, untracked, unmerged, hidden;
  0 to 5), because `gitsafe.Status` has no file count. Reopened by the
  gitsafe task that adds a file counter (after T151, PR #210): `dirty`
  then becomes the file count. Salvage's `dirty-at-last-facts`
  (REQ-0237) reads the same field, so it carries the same meaning until
  then.
- The gap line compares head, branch and dirty only (the three things
  08 8.3 lists, plus a repo added or removed); stashes, upstream and
  ahead/behind are stamped but never raise it.
- SessionStart and SessionEnd failures are recorded, cleared and read
  through T054's store, `hook-failures/` below julieta state, so the
  SessionStart print shows every recorded failure, the git hooks' too
  (08 8.2). A success of a hook clears its failure for the same repo
  (the manifest repo dir, `./api` and `api` being one), and one
  recorded before the repo was known (repo empty). The stored message
  is cut at 300 bytes. `hooks.json` keeps only `sessionStartAt` and
  `sessionEndAt`. `julieta status` does not list the failures yet: the
  Acceptance line "`julieta status` lists it" waits for a status
  section that reads the store, recorded in
  `docs/handoff/pending/0000000000782g86tsyzte1t16-julieta-status-reads-the-hook-failure-store.md`
  (copying the failures into `setup.json` was removed because two
  writers of it lost each other's changes). Edit of `internal/hooks`:
  the constants `SessionStart` and `SessionEnd`, and an optional
  `message` member of `Failure` (omitted when empty); its tests pass
  unchanged and one test is added.
- `setup.json` has one writer protocol: `setup.UpdateState(home, f)`
  reads, changes and writes it under the lock `state.lock`, and never
  writes a state it cannot read. `julieta setup` records its state
  through the same lock, reading the state fresh, so a clear of
  `default-branch-moved` made while setup ran is not undone (it keeps
  its old rule of replacing a state it cannot read, and says so). The
  SessionStart hook clears `default-branch-moved` only through
  `UpdateState`, and prints an unreadable `setup.json` as one line.
  Edit of merged `internal/cmd/julieta/setup`: `state.go`, `setup.go`
