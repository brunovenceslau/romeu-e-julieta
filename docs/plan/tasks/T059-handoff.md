its bound, the three gap-line goldens, SessionEnd and SessionStart in
both orders.

Re-plan (2026-10-12): Kept. The J5 scenario function moves to T075 with
the other remaining scenario functions; the container e2e asserts both
hook orders here, as the row says. The manifest type comes from T135,

- Acceptance:
  - `write` refuses a narrative without its headings (six for `final`)
    and stamps the front matter; `--facts` has no body;
    `schemas/handoff.v1.json` is generated.
  - `handoff write` takes the store lock of its target dir before its
    first git read and releases it at exit; with the lock held by
    another process, `handoff write --facts` waits until it is released
    (a test seam, no sleep).
  - After each facts write, `handoff write --facts` keeps the newest 50
    facts files and every narrative in `handoff/`; the newest facts file
    is never removed (08 8.1, 8.6).
  - The handoff reader returns the greatest ULID among `clear` and
    `final` as the narrative; a later `facts` file does not hide it. The
    decoder is `go.yaml.in/yaml/v3` with `KnownFields(true)`: a front
    matter with an anchor, alias, merge key or include, a duplicate key,
    an unknown key, or over the file cap, is refused, one fixture each;
    the reader refuses a newer version with `RJ-311`; a fuzz target over
    the handoff file decoder has its seeds committed (10 10.1, Fuzz).
  - The container e2e runs SessionEnd and SessionStart in both orders
    (Q22). julieta records in its state the time of the last
    SessionStart and SessionEnd hook runs (08 8.2).
  - `show --hook` prints, in this order, julieta's warnings (one line
    each, the kinds of 08 8.2 item 1), the fixed line `built-in memory
    is disabled, use julieta memory add`, the latest narrative or the
    gap line of 08 8.3, the facts that changed since it, open entries
    not tagged `lesson` newest first, and open `lesson` entries newest
    first; each item carries its repo label, and agent-written text sits
    under the line that says so. Goldens (10 10.1): the print whole, and
    the print cut at 8 KiB, whose last line is `<n> more entries:
    julieta memory list` and whose warnings are all present.
  - The SessionStart print has three goldens under
    `internal/handoff/testdata/`: whole, cut at its bound, and
    "SessionStart prints every warning when they exceed the bound" (10
    10.1; 08 8.2).
  - The first `show --hook` after a default-branch move prints
    `default-branch-moved` and clears it; the second does not print it.
  - A forced failure in `handoff show --hook` and in `handoff write
    --facts` exits 0, prints one stdout line naming the failure and
    `julieta status`, and records a hook failure; `julieta status` lists
    it and the next SessionStart prints it until the hook next succeeds
    (08 8.2).
  - `list` prints one line per handoff file with its kind, and `--json`
    one document.
  - The three goldens of the SessionStart gap line that 08 8.3 names
    (Resume): `/handoff` then `/clear` prints no line, a facts-only end
    with new commits prints it, and `/handoff`, a commit, then `/clear`
    prints it (round 18, ship gate round 1, F9).
  - The package takes the clock and the ULID entropy source as injected
    values, every ULID comes from `canon.NewULID`, and its tests fix
    both (10 10.4).
