# T035 - `memstore`, `memstore/write` and the memory commands

Earlier title: `memstore`: the shared readers.

Goal: `memstore`, `memstore/write` and the memory commands: the readers
on `os.Root` with the allowlist and the caps, the `Store` with the lock
and atomic writes, `memory add|list|show|edit|check`, and `setup`'s
`memory check` as one file under `setup/`.

Re-plan (2026-10-12): Kept; T057 (`memstore/write` and the memory
commands) is folded in, and its rows are copied below: julieta stamps
`id`, `createdAt` and `updatedAt`, and a supplied id or timestamp is an
error; two processes lose no entry; a duplicate open entry prints the
existing id and writes nothing; `check` exits 6 on a layout violation;
the allowlist cases of I24. The manifest type comes from T135, which
this task needs; `after: T051` for the setup seam file, and `after:
T123` because the record of memory as plain per-repo files is a review
order (12 12.5):
[ADR 0021, keep memory as plain per-repo files](../../adr/0021-keep-memory-as-plain-per-repo-files.md). The schema is generated by `tools/schemagen` (T125).

- Operator: no.
- Acceptance:
  - The allowlist table refuses, through `os.Root` and Lstat, a symlink,
    a FIFO, a dotfile, a `.git` directory, a `..` name and a top-level
    name outside the four of 08 8.1 (`entries/`, `handoff/`,
    `snapshot/`, `salvage/`); the caps are enforced.
  - Memory dirs are 0700 and every file julieta writes is 0600 (08 8.1).
  - `julieta setup` removes a `.tmp-<ULID>` older than its own start and
    keeps a newer one.
  - The store lock is `$HOME/.local/state/julieta/locks/<dir>.lock`, and
    no file appears in the memory dir while it is held.
  - A memory entry file is self-contained: copying `entries/` whole is a
    complete move, and the store lock is recreated on first use (08
    8.1).
  - The entry decoder is `go.yaml.in/yaml/v3` with `KnownFields(true)`:
    a front matter with an anchor, alias, merge key or include, a
    duplicate key, an unknown key, or over the file cap, is refused, one
    fixture each; the reader refuses a newer version with `RJ-311`; a
    fuzz target over the memory entry decoder has its seeds committed
    (10 10.1, Fuzz).
  - `memory add` on content whose `memory-content` digest equals an open
    entry's prints the existing entry's id and writes nothing (04 4.1,
    Idempotency), so a rerun after a timeout adds nothing.
  - `tools/ci imports` fails a romeu-linked package that imports
    `memstore/write` (I24).
  - `schemas/memory-entry.v1.json` is generated.
  - The package takes the clock and the ULID entropy source as injected
    values, every ULID comes from `canon.NewULID`, and its tests fix
    both (10 10.4).
  - `setup/steps.go` is the ordered step list of T051 that this task
    extends by one line (rule 14 of `docs/plan.md`), and the record of
    memory as plain per-repo files, ADR 0021, is merged (12 12.5).
- Acceptance (from T057, folded):
  - julieta stamps `id`, `created` and `updated`; a supplied id or
    timestamp is an error.
  - Two julieta processes writing one store lose no entry (10 10.1,
    Concurrency).
  - `list --query <text>` filters, and `edit --status done` closes an
    entry; there is no `memory rm` and no `memory search` (04 4.3).
  - `memory check` exits 1 on an unmounted or unwritable directory, and
    6 (`check-findings`) on one that breaks the layout allowlist;
    `setup` gains `memory check` and the agent memory dir check (04 4.3;
    08 8.1).
- Verify: `go test ./internal/memstore/...`.

Decisions taken while building (2026-10-20), each with what reopens
it:

- `Put(entry)` of 08 8.1 is `Store.Add` and `Store.Edit`, and the raw
  write is unexported, so no caller can supply an id or a time. Reopened
  by a writer that needs to put a whole entry, such as an import.
- The `--json` documents of `memory add`, `list`, `show` and `edit` are
  one format, `julieta-memory.v1`, named after the `memory` command.
  Reopened by a subcommand whose output does not fit it.
- The body of `add` and `edit` is the flag `--body`: an argv element,
  which Linux caps at 128 KiB, under the 1 MiB file cap. Reopened by
  `handoff write`, which reads stdin, if memory should read it too.
- A title is one line of printable text of at most 200 bytes; a tag
  matches `[a-z0-9][a-z0-9-]{0,31}`, at most 32 tags, distinct. Reopened
  by an entry those refuse.
- A member of `entries/` that is not a file `<ULID>.md` is the finding
  `entry-name`, since the readers could not read it. Reopened by a
  layout change of 08 8.1.
- A leftover temporary file and a `handoff/` over its cap print as
  `note` lines on stderr: 04 4.1 lists no warning slug for either.
  Reopened by a slug for them in 04 4.1 (the pending note below).
- The agent memory dir check reads the dir through the seam
  `agentMemoryDir` of `setup/memory_check.go`, which no agent profile
  fills yet. Reopened by T079, whose profile names the dir.
- The decoder reads tags in any order, as the example of 03 3.9 writes
  them, and sorts them; `Encode` writes them sorted. Reopened by a tag
  order with meaning.
- The atomic write stays in `memstore/write` rather than renameio,
  because REQ-0654 names the temporary file `.tmp-<ULID>` (decided on
  2026-10-20), and the store lock is a flock of `golang.org/x/sys/unix`
  rather than `gofrs/flock` (decided on 2026-10-20). Reopened by a
  library that names its temporary files, or a lock need beyond flock.
- `check-findings` (`RJ-328`, exit 6) is declared once, in
  `internal/cli/errors.go`, since commands of both binaries raise it
  (decided on 2026-10-20, on the `contracts` surface). Reopened by a
  check whose findings need a fix text of their own.
- Deferred on 2026-10-20, each a pending note with its trigger: a
  total-bytes cap on `entries/`
  (`docs/handoff/pending/a-total-bytes-cap-on-entries-of-a-memory-dir.md`),
  a bounded wait on the store lock
  (`docs/handoff/pending/a-bounded-wait-on-the-store-lock.md`), the
  warning slugs of the two `note` lines
  (`docs/handoff/pending/warning-slugs-temp-file-and-handoff-cap-in-04-4-1.md`),
  and a hard-link rule
  (`docs/handoff/pending/a-hard-link-rule-for-memory-dirs.md`).
  Each is reopened by the trigger its note names.
