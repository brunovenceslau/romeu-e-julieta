# T008 - The CLI contract: exit codes, error ids per package and registration by file

Merged on 2026-10-18 in pull request #109. The text below is the one
written at the re-plan.

Earlier title: The CLI contract: the error table, exit codes and the
dispatcher.

Goal: The CLI contract: exit codes, the error ids of 04 4.4 declared per
package with the union test, the text and `--json` forms, command
registration by `init`, and the generated reference pages. `owns` names
the files of `internal/cli` by name, since `internal/cli/writer.go` is
T007's and `internal/cli/errorids_exempt.yaml` is T073's; a file of the
package this list does not foresee is added to it in this task's pull
request.

Re-plan (2026-10-18, second): Changed, by
[ADR 0016, lint generated files and give each one the full generated header](../../adr/0016-lint-generated-files-and-give-each-one-the-full-generated-header.md):
a generated Go file carries the generated header, and the linters read
it.

Re-plan (2026-10-18): Changed. `internal/cli/exitcodes_gen.go` is a
generated output of rule 1 of `docs/plan.md`, owned by no task like the
pages it is generated with, so `owns` drops `internal/cli/*_gen.go` and
names `internal/cli/completion*.go`, the files of the `completion`
command, and `tools/ci/generator_cli*.go`, so it takes in the test of
the import boundary, which runs `go list` for each target, since a test
under `internal/` imports no `os/exec`. The tests of the generated check
that read this repository register its generators in a registry of
their own, so the two files that hold them take in the generators of
the command line.

Re-plan (2026-10-17): Changed, by
[ADR 0015, adopt spf13/cobra for the command line of romeu and julieta](../../adr/0015-adopt-spf13-cobra-for-the-command-line-of-romeu-and-julieta.md).
The command line is cobra with pflag, which enter `go.mod` here as their
first importer (rule 7 of `docs/plan.md`), so this task owns `go.mod`
and `go.sum` and comes before T125 and T053. The registry by file stays;
each definition holds a function that returns its `*cobra.Command`, and
`internal/cli` assembles the binary's tree on each run. A generator
lives in the package that owns its data (ADR 0015, decision 7): the
generator of the error table's pages in `internal/cli`, and that of the
per-command reference pages in `internal/cli/clidoc`, the one importer
of `cobra/doc`, which no binary imports and which hands `tools/ci` both.
The generated check of `tools/ci` holds no generator; one file,
`tools/ci/generator_cli.go`, imports `internal/cli/clidoc` and the two
`internal/cmd/<binary>/all` packages that link the commands in, and
registers the generators with `check.RegisterGenerator` (02 2.1,
REQ-0121). The pages join the `-text` list of `.gitattributes`. A check
of its own would add a row to the step table of 10 10.2 for a generator
that judges nothing.

Re-plan (2026-10-12): Kept, changed. Each package declares its ids in
its own `errors.go`, taken from 04 4.4; one test collects the union.

- Acceptance:
  - Lands before its module's place in the order of 12 12.2 (Q26):
    `spec`, `state` and `gitsafe` return its error ids (03, opening; 01
    1.6; 10 10.6), and it needs nothing from the modules between.
  - `internal/cli` exports `Env` (the escaping writers for stdout and
    stderr, the clock, the ULID source, the version stamp, the settings
    path and the subprocess runner the command needs), `Define` and
    `Register`, called from a package-level `var _ = cli.Register(def)`
    in each command package, and `cli.Main(ctx, args, env)`, which
    assembles the binary's cobra tree from the registered definitions,
    runs it with `ExecuteContext` and maps the error id to the exit
    code; a fixture command in the package's tests registers and runs
    through `Main` with a fixed clock. A definition names its binary,
    its command path (a command and, for a subcommand, its subcommand)
    and a function that returns its `*cobra.Command`, whose `RunE` gets
    the `Env`. The field list is this task's to settle (rule 6 of
    `docs/plan.md`).
  - A definition is registered through one constructor whose arguments
    are the five side-effect fields; a fixture definition that leaves
    one unset fails `go test ./internal/cli/...`. A duplicate command
    path panics at `init`, and a test asserts the registry's order and
    names. The lock field of each definition is checked against the
    list of 04 4.1 Locking by a table over the definitions. A definition
    with no `Args` validator fails registration, and a group command
    above subcommands takes none, so `<group> <typo>` is the error
    `usage`. Each run builds a new tree, so no package holds a root
    command and a test builds its own (ADR 0015, decision 2).
  - Flags are GNU-style (04 4.1, Parsing): a test runs a fixture with a
    flag after an argument, `--name=value`, a one-letter short form and
    `--`; `--help`, `-h` and `help <command>` print the help of the
    binary, of a command with subcommands and of a subcommand, each
    with the exit-code section and each flag's value name and default.
    A single-dash long flag, an unknown command, subcommand or flag,
    an argument count a command refuses and `help <unknown>` are the
    error `usage` (`RJ-349`, exit 2), whose hint names the help to read;
    an error a command returns with no `*cli.Error` is `internal`
    (`RJ-348`). A test runs the tree with `os.Stdout` and `os.Stderr`
    swapped for pipes and finds them empty on every path.
  - Every byte the tree prints goes through the CLI writer (I29): the
    tree's output and error streams are the writers of `Env`, its help
    and usage functions are this package's, and `SilenceErrors` and
    `SilenceUsage` keep cobra from printing errors of its own; a test
    feeds a control character and a line feed through an argument, a
    flag error and a detail and finds them escaped, one value per line.
  - Both binaries have their own `completion` command for bash, zsh and
    fish (04 4.2, 04 4.3), whose script and `__complete` output are the
    raw-output exception of 04 4.1 (REQ-0270); a test runs `completion
    bash` and `__complete` on the fixture tree, and another holds a
    completion function to REQ-1245.
  - A test holds the import boundary of REQ-1246: cobra only in
    `internal/cli`, `internal/cli/clidoc` and `internal/cmd/**`,
    `cobra/doc` only in `internal/cli/clidoc`, which only `tools/ci`
    imports (REQ-1247), so `tools/ci imports` passes, and no target of
    `cmd/romeu` or `cmd/julieta` linking `internal/cli/clidoc`,
    `cobra/doc`, go-md2man, blackfriday or mousetrap.
  - The two `internal/cmd/<binary>/all/doc.go` files name the package's
    one purpose: the assembled command set each binary's `main.go`
    imports once.
  - An error has an id `RJ-<nnn>`, one sequence that carries no meaning,
    a slug, an exit code, a message and a fix hint, declared in the
    `errors.go` of the package that returns it, with the ids of 04 4.4;
    the text and `--json` forms match 04 4.1, and a `--json` error
    carries `details`, the object the text form prints after the first
    line; tests assert ids, not message text.
  - The id of an error is that of the outermost `*cli.Error` found by
    `errors.As`; a wrapper keeps the inner id (`%w`, no `cli.Error` of
    its own); a test asserts an id through the one helper of
    `internal/cli`'s test-support package, and the meta-test over the
    module's `_test.go` files is T073's. An error chain with no
    `*cli.Error` exits 1 as the error `internal` (`RJ-348`), and a test
    holds that path (item 17 of Decisions of the re-plan in
    `docs/plan.md`, decided on 2026-10-12, as 04 4.4 and 10 10.1 state
    it).
  - The union test reads the rows of 04 4.4 while it holds rows, then
    the source table of `docs/reference/errors.md`, and fails on a
    duplicate id, an id not in 04 4.4, a row marked retired that a
    package declares, and an id whose slug or exit code differs from its
    row; an id of 04 4.4 that no package declares is listed by `go test
    -run TestErrorIDsPending -v` and fails only from T073. A row marked
    retired is skipped by the union test and kept in the table with its
    last text. `check-findings` maps to exit 6 and is the only id that
    does.
  - A warning is a row of the table by slug with no id; a test fails a
    slug printed by the CLI writer as a warning that is no row.
  - The fix hint of `RJ-338` is the one fixed text that 04 4.4 quotes,
    and a test fails when the table's hint differs from it by a byte;
    the reference is that row's quoted text, read from the page by the
    test with its code-span backticks stripped, so the table's hint
    holds no backtick (round 17, R17-06; round 18, R18-A7). A test fails
    a fix hint that starts with neither a command line nor `decide:`,
    except that one hint. A table test fails a hint that names
    `--overwrite-drift`, `--accept-loss` or `--force` without a clause
    on what the flag discards.
  - A test reads every registered command definition and fails a fix
    hint (other than `RJ-338`'s) or a `--help` example whose command,
    subcommand or flag the definitions do not have; it runs on every
    pull request, so each command task is checked when it registers.
  - Each id has a recovered-in cell, a `docs/guide/` anchor or `none:
    <reason>`; a test fails an id without one, and `errors.md` links it.
  - `go generate` writes one `docs/reference/<binary>/<command path>.md`
    page per registered command with `github.com/spf13/cobra/doc`, from
    the tree `cli` assembles, through the generator in
    `internal/cli/clidoc`, with the P marker and the appending list
    (12 12.3, REQ-1109); a fixture definition shows the page.
  - `go generate` writes the three consumers of the table (12 12.3): the
    exit-code sections of `--help`, `docs/reference/errors.md` and
    `docs/reference/exit-codes.md`, the pages with the generated-file
    header and front matter; the exit-code section of `--help` and
    `docs/reference/exit-codes.md` list 130 and 143 with the precedence
    sentence of 04 4.1 Signals. The exit-code section of `--help` is
    the Go file `internal/cli/exitcodes_gen.go`; a Go file a generator
    writes is named `*_gen.go` and carries the generated header of
    REQ-1117, and the linters read it (ADR 0016).
