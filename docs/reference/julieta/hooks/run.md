# julieta hooks run

run the chain of a git hook: julieta's action, .githooks/<hook>, then the local hook

### Synopsis

Git runs this through the scripts of the dispatcher, which pass the hook name first and then the hook's own arguments.
A flag before the hook name, such as --help, is read by julieta; whatever follows the name is the hook's.

The stages run with pipes for standard input, output and error, not the terminal, and each in a process group of its own. A job a hook leaves running in the background is ended when the hook ends, which plain git does not do. Their output goes through the CLI writer, so terminal controls in it are escaped.

```
julieta hooks run <hook> [args] [flags]
```

### Examples

```
julieta hooks run pre-commit
julieta hooks run commit-msg .git/COMMIT_EDITMSG
```

### Options

```
  -h, --help   help for run
```

### Side effects

- **P** (preflight): no
- Lock: no
- Appends on each run: nothing
- Writes a julieta snapshot: no
- Idempotency: a second run with no input change leaves files and refs as they were

### Exit codes

| Exit | Meaning |
|---|---|
| 0 | ok |
| 1 | the operation failed |
| 2 | usage or precondition |
| 3 | approval required |
| 4 | drift detected, or an interrupted promotion abandoned |
| 5 | refused to protect data |
| 6 | the check ran and found what it checks for |
| 130 | ended by SIGINT |
| 143 | ended by SIGTERM |

A signal wins over a failure the command had already found (1 to 6); a command that had finished its work keeps 0.
