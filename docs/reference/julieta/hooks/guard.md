# julieta hooks guard

the PreToolUse hook: refuse a merge, a v* tag, a release, and gh api changes to rulesets or repository settings

### Synopsis

The agent runs this as its PreToolUse hook, with the document of the tool call on stdin.
It exits 2, which refuses the call, when the Bash command merges a pull request (gh pr merge, gh api to pulls/<n>/merge, or the GraphQL mergePullRequest or enablePullRequestAutoMerge), pushes a v* tag (a ref of refs/tags/v or a glob of refs/tags/, a bare release version, after tag, or every tag by --tags, --follow-tags or --mirror, or a tag ref made through gh api), creates or deletes a release (gh release create or delete, or gh api to releases), or changes a ruleset or a repository's settings through gh api; the refusal on stderr says the action is the maintainer's and names the route, an issue or the handoff. It exits 0 for any other call.

The command is parsed as bash parses it, so a command inside a list, a pipeline, a subshell, a function or a command substitution counts, and a heredoc's text or a comment does not. A document it cannot decode, and a command it cannot parse, exit 2 as well: the guard fails closed. It is a guard against mistakes, not against an agent that hides a command or edits its own hook.

```
julieta hooks guard [flags]
```

### Exit codes

| Exit | Meaning |
|---|---|
| 0 | ok |
| 1 | the operation failed |
| 2 | usage or precondition |
| 3 | approval required |
| 4 | drift detected, or an interrupted promotion abandoned |
| 5 | refused to protect data |
| 6 | the check ran and found what it checks for |
| 130 | ended by SIGINT |
| 143 | ended by SIGTERM |

A signal wins over a failure the command had already found (1 to 6); a command that had finished its work keeps 0.
