# julieta hooks guard

the PreToolUse hook: refuse gh pr merge, a push of a v* tag and gh api changes to rulesets or repository settings

### Synopsis

The agent runs this as its PreToolUse hook, with the document of the tool call on stdin.
It exits 2, which refuses the call, when the Bash command merges a pull request (gh pr merge), pushes a v* tag (a ref or bare name of one, after tag, or every tag by --tags, --follow-tags or --mirror), or changes a ruleset or a repository's settings through gh api; the refusal on stderr says the action is the maintainer's and names the route, an issue or the handoff. It exits 0 for any other call.

A document it cannot decode exits 2 as well: the guard fails closed. It is a guard against mistakes, not against an agent that hides a command or edits its own hook.

```
julieta hooks guard [flags]
```

### Examples

```
julieta hooks guard <pre-tool-use.json
julieta hooks guard --json <pre-tool-use.json
```

### Exit codes

| Exit | Meaning |
|---|---|
| 0 | ok |
| 1 | the operation failed |
| 2 | usage or precondition |
| 3 | approval required |
| 4 | drift detected, or an interrupted promotion abandoned |
| 5 | refused to protect data |
| 6 | the check ran and found what it checks for |
| 130 | ended by SIGINT |
| 143 | ended by SIGTERM |

A signal wins over a failure the command had already found (1 to 6); a command that had finished its work keeps 0.
