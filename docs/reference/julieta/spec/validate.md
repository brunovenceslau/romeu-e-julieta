# julieta spec validate

check project specs without the host settings

### Synopsis

Decodes each project spec strictly and checks it against the schema and the name and path rules of 03 3.1, each file alone and the files together, and prints one line naming the rules only romeu checks, since they read host settings. Every entry of a projects/ directory that holds a file given and is not *.yaml, a subdirectory or a dotfile among them, is a finding. So is a spec whose manifest would be at least 32 KiB over the cap: julieta measures it with stand-ins for what only romeu knows, a lower bound, and romeu sync measures it again. With --catalog it also reads each repo's mise.lock at the tip of its ref with a shallow fetch from origin and reports each backend:tool the embedded egress catalog and the spec's egress.tools lack, a finding, and a lock that does not parse or that gitsafe refuses, a finding too; it warns lock-host-gated for each lock host the catalog does not produce, and for an artifact URL with no host it can read. A pass is no gate on those hosts: romeu sync gates them. --catalog fetches from origins the specs name, so the config repo's CI runs it for trusted authors only, or under restricted egress. An origin it cannot read, or one that lacks the ref or a default branch, is fetch-failed, exit 1. Any finding is exit 6; a file that cannot be read is exit 2. With --json it prints one document of the format julieta-spec.v1, the warnings among its members, and stderr is then empty but for an error.

```
julieta spec validate <file>... [flags]
```

### Examples

```
julieta spec validate projects/foo.yaml
julieta spec validate --catalog projects/*.yaml
```

### Options

```

  -h, --help      help for validate
      --json      print one JSON document
```

### Exit codes

| Exit | Meaning |
|---|---|
| 0 | ok |
| 1 | the operation failed |
| 2 | usage or precondition |
| 3 | approval required |
| 4 | drift detected, or an interrupted promotion abandoned |
| 5 | refused to protect data |
| 6 | the check ran and found what it checks for |
| 130 | ended by SIGINT |
| 143 | ended by SIGTERM |

A signal wins over a failure the command had already found (1 to 6); a command that had finished its work keeps 0.
