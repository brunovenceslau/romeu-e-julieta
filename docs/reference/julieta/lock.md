# julieta lock

lock the tools of a repo's mise.toml, or check that its mise.lock is fresh

### Synopsis

Runs mise lock for the repo of the working directory, or of --repo, with --platform linux-x64,linux-arm64 and the platforms of the repo's lockfile_platforms setting, and rewrites mise.lock. With --check it writes nothing: it fails with exit 6 on a tool of mise.toml with no lock entry, on a lockable entry that lacks linux-x64 or linux-arm64, on an entry without a well-formed sha256 checksum (unless .julieta/lock-exceptions excuses its tool) and on a file that does not parse. It warns lock-unknown-tool, and still passes, for a backend:tool the embedded egress catalog does not have.

```
julieta lock [flags]
```

### Examples

```
julieta lock
julieta lock --repo api
julieta lock --check
```

### Options

```
      --check         check that mise.lock is fresh and write nothing
  -h, --help          help for lock
      --repo string   the dir of the repo, as the manifest names it; the repo of the working directory by default
```

### Side effects

- **P** (preflight): no
- Lock: no
- Appends on each run: nothing
- Writes a julieta snapshot: no
- Idempotency: a second run with no input change leaves files and refs as they were

### Exit codes

| Exit | Meaning |
|---|---|
| 0 | ok |
| 1 | the operation failed |
| 2 | usage or precondition |
| 3 | approval required |
| 4 | drift detected, or an interrupted promotion abandoned |
| 5 | refused to protect data |
| 6 | the check ran and found what it checks for |
| 130 | ended by SIGINT |
| 143 | ended by SIGTERM |

A signal wins over a failure the command had already found (1 to 6); a command that had finished its work keeps 0.
